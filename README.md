# Council Check

A text-based council claim checker. The web app extracts traceable factual claims in English, Spanish, and Catalan. OpenAI Decisions routes claims to official datasets or web research, then an evidence-grounded assessment publishes a verdict, cited sources, uncertainty, and code-computed calculations.

## Run the app locally

Use Node.js 22.18 or newer, npm, and Python 3 (for the extension ZIP packaging).

```sh
npm install
npm run dev
```

Open http://localhost:8787. Paste text, start extraction, and reload the resulting URL. The Workflow publishes claims and per-chunk progress. Claim cards update from research to assessment and completion, with partial technical errors shown separately. Local submissions persist under the ignored Alchemy state directory in tooling/infra. Keep that directory to retain local data.

Local development emulates Workers, R2, a SQLite Durable Object, and Workflows using Alchemy/Miniflare. The pinned Alchemy provider requires an account identity even in local mode, so the infrastructure script supplies a local-only emulator identity. The app can start without Cloudflare credentials. Add OPENAI_API_KEY and ALCHEMY_PASSWORD to the ignored root .env for extraction. Docker supplies the optional local evidence database.

The web assets are built when dev starts. For frontend hot reload, keep the main dev process running and start `npm run dev --workspace @council/web` in another terminal. Open Vite's URL. It proxies /api to port 8787. Rebuild or restart the main dev command to serve updated frontend assets on port 8787.

## Checks and development deployment

```sh
npm run typecheck
npm run lint
npm run build
npm test
```

Build packages the Chrome extension, creates the web assets (including its ZIP download), and dry-runs Worker bundling. The focused test suite covers traceable compound claims, supplied context, invented-quote rejection, and multi-chunk Unicode offsets. Live API and browser smoke checks cover the processing path.

To deploy a development environment, configure OAuth with `npx alchemy configure` or supply Cloudflare credentials in a root .env using .env.example. Set ALCHEMY_PASSWORD to encrypt deployment state, then run `npm run deploy:dev`. The account needs access to Workers, R2, Durable Objects, and Workflows. Alchemy provisions the bucket, bindings, Workflow, and SQLite Durable Object migration. Deployment credentials are server-side. Set CLOUDFLARE_PROFILE in .env if the configured profile has a custom name. Local and deployed data use separate stores.

The checked-in Wrangler configuration supports dry-run builds and standalone Wrangler local inspection. Alchemy owns infrastructure deployment. Both configurations pin compatibility date 2026-07-15 to match the pinned Alchemy emulator.

## Submission API

`POST /api/runs` accepts the following JSON and returns HTTP 202 with runId and a relative web URL.

```json
{
  "submissionKey": "a UUID generated by the caller",
  "text": "Original text to preserve",
  "explanationLanguage": "ca",
  "source": { "url": "https://example.org/source", "title": "Council passage" },
  "passages": [{ "start": 0, "end": 12, "speaker": "Councillor", "startSeconds": 10 }]
}
```

Only submissionKey and text are required. Text must contain a non-whitespace character and be at most 200,000 Unicode characters. Passage offsets are JavaScript UTF-16 offsets into the original text, and end is exclusive. Original whitespace is preserved. The limit counts Unicode code points.

Reuse a submissionKey after a lost response. The same validated payload returns the original run, while a different payload with that key returns HTTP 409. The browser retains its current draft/key in session storage and generates a new key when text changes. `GET /api/runs/:runId` returns the saved submission, stage, timestamp, and revision. Invalid or missing IDs return HTTP 404. Links grant access to submissions in this single-user scaffold.

La base se llama `council`, escucha en localhost y utiliza el usuario `council`. Si cambias `POSTGRES_PORT` o `POSTGRES_PASSWORD`, exporta las variables para que las lean tanto Compose como el script. El script también acepta `DATABASE_URL`.

python3 scripts/ingest.py --check

Por defecto se descargan todos los CSV del padrón que CKAN anuncia. La carga continúa si falla una fuente, informa del error y sale con código distinto de cero. Cada fuente se escribe en una transacción. Volver a cargar el mismo recurso conserva su versión y actualiza la fecha de la última descarga. Los CSV mantienen las columnas y los valores originales como JSONB, incluidos ceros iniciales en códigos. INE queda en una fila por observación, con los campos de su serie. Las fichas se vectorizan con `text-embedding-3-small` y el vector se vuelve a generar si cambia su texto.

## Typed evidence tools

Our query integration reuses the database/document helper added by the teammate's B-path merge. Local Alchemy defaults to the Docker connection above. A deployed Hyperdrive origin uses HYPERDRIVE_ORIGIN or DATABASE_URL. Python data preparation uses DATABASE_URL directly.

The development API provides POST /api/dev/evidence/search, /inspect, and /query with the input schemas in packages/contracts/src/database.ts. GET /api/dev/evidence/catalogue retains the existing catalogue-list response. Document routes remain available after applying the teammate's document migrations and extraction commands.

Search works without embeddings. Optional query vectors require text-embedding-3-small and 1536 dimensions. inspect_dataset returns available resources, fields, units, sample rows, and immutable snapshot references. For multi-resource datasets, choose a resourceKey or snapshotId explicitly. Continue pagination with the returned snapshotId.

Example query body for POST /api/dev/evidence/query follows.

```json
{
  "datasetId": "incasol",
  "filters": [
    { "field": "Codi territorial", "op": "eq", "value": "08019" },
    { "field": "Àmbit territorial", "op": "eq", "value": "Municipi" },
    { "field": "Tram de preus", "op": "eq", "value": "> 600 euros/mes" },
    { "field": "Any", "op": "eq", "value": "2026" },
    { "field": "Període", "op": "eq", "value": "abril-juny" }
  ],
  "aggregate": { "operation": "avg", "field": "Renda" },
  "limit": 25
}
```

Filters, fields, ordering, and aggregate operations are validated against the selected resource. Territory codes remain strings. Row data retains the full original JSON, including period/unit fields; optional fields also returns selectedValues. Results identify whether displayed rows are a sample. Aggregations cover all matched rows in the pinned snapshot. Missing numeric values produce a missing_numeric_values result with no numeric answer.

The SQL baseline remains db/schema.sql, mirrored by apps/api/src/db/schema.ts. Keep additive migrations under db/migrations. Docker's init script runs only for a fresh volume; scripts/extract_documents.py --migrate-only applies the existing ordered migrations to either Docker or Neon using its migration ledger.

## Research and assessments

Each claim runs an initial pass with at most three application tool actions. Up to two claims are researched concurrently. Stored-data queries pin snapshots and retain their original rows, periods and aggregate coverage. General factual claims use hosted web search and exact passages reconstructed from retrieved source text.

Decisions supplies checkability, topic and evidence-scope triage. The assessor independently evaluates the retained sources. Numerical calculations verify source values and units and are recomputed by code. Technical failures remain separate from insufficient evidence, and completed runs can contain partial claim errors.

GET /api/runs/{runId}/claims/{claimId} returns the shared ClaimDetail contract. The [frontend handoff](.viktor/frontend-contract.md) includes evidence/assessment fields and real rendering fixtures. Shared cards are exported by @council/ui for both clients.

Model IDs are configurable through EXTRACT_MODEL, DECISION_MODEL, RESEARCH_MODEL, SEARCH_MODEL, and EXPLAIN_MODEL. Model requests use explicit timeouts. This initial pass precedes the configurable longer research loop in TASK-005.

### Provider request examples

The search integration sends `POST https://api.openai.com/v1/responses` with this shape (the assertion is placed in the input, and the API key is a server-side Authorization header):

```json
{
  "model": "gpt-6.2-astra",
  "store": false,
  "reasoning": { "effort": "low" },
  "max_tool_calls": 1,
  "max_output_tokens": 1000,
  "tools": [{ "type": "web_search", "search_context_size": "low" }],
  "tool_choice": "required",
  "include": ["web_search_call.action.sources"],
  "input": "Find primary evidence for: Barcelona is the capital of Catalonia. Start with official sources."
}
```

The completed response provides `output[].action.sources[]` and/or message `content[].annotations[]` URL citations. These identify candidates, not verified quotations. The app reads at most two candidate URLs and reconstructs exact retained source passages; a generated summary is never stored as a quotation. Search has a 30-second request timeout and non-completed/error responses are technical failures.

Decisions sends `POST https://api.openai.com/v1/decisions`, for example:

```json
{
  "model": "gpt-6-luna",
  "input": "{\"assertion\":\"Barcelona is the capital of Catalonia.\"}",
  "questions": [{
    "type": "choice",
    "name": "topic",
    "instructions": "Which topic best describes the assertion?",
    "choices": [{ "value": "municipal" }, { "value": "general" }]
  }]
}
```

The response contains typed `answers`, such as `{"type":"choice","name":"topic","choice":"municipal"}`. Decisions has a 15-second timeout. Checkability classifies the kind of assertion independently of whether it is true. Probabilities and routing decisions are not factual verdicts.

## Documents, transcripts and checkability

Paste text or import `.txt`, `.srt` or `.vtt` in the web app. Text is preserved exactly; recognized subtitle, bracketed and copied YouTube timestamps supply optional passage metadata. Source URL/title and explanation language can be set before checking. YouTube URL retrieval/transcription is a separate producer using the unchanged text API.

The workflow extracts overlapping text sections and starts two deterministic checking lanes as sections publish. Progress shows extraction and completed claims separately. Exact repeated assertions with matching scope can share a canonical check while retaining occurrence offsets, speakers and timestamps. Changed numbers, dates and qualifications stay distinct. Completion waits for extraction and every published claim; partial provider failures are shown alongside successful results.

Short passages (up to 2,000 characters) receive an advisory OpenAI Decisions checkability notice: factual assertion, opinion/prediction or needs context. This is separate from the evidence-based truth verdict and never suppresses normal extraction. The extension offers a prominent link to the same web run for passages over 5,000 characters or runs with more than eight claims.

Quotes are anchored to original text. Unique mechanical whitespace/typography differences can be resolved back to an exact original span. Unanchored candidates are excluded with visible extraction warnings, while valid claims continue. The original input remains available for coverage review. The 200,000-character acceptance limit does not imply instant processing; elapsed time depends on factual density and source availability.

See [the demo runbook](docs/demo-plan.md) and [ready-to-import examples](eval/demo). The supplied long-document sample is 13,591 characters from official minutes pages 8–11, with source version and page metadata recorded in its JSON companion.

### Importar un tramo de YouTube

`POST /api/runs/youtube` acepta un enlace de vídeo de YouTube (página `watch` o `youtu.be`), un inicio y fin en segundos enteros y el UUID de la solicitud. El intervalo máximo es de 180 segundos. El Worker devuelve `202` con el mismo `{ runId, url }` que una entrada de texto. En los reintentos usa el mismo UUID y los mismos parámetros.

El binario de extracción corre fuera de Cloudflare Workers. En local, instala la dependencia y ejecuta el proceso Python en paralelo a `npm run dev`:

```sh
.venv/bin/pip install -r scripts/requirements-youtube.txt
# Exporta el mismo YOUTUBE_IMPORT_TOKEN en ambos procesos.
.venv/bin/python scripts/youtube_import.py
# En la terminal que ejecuta npm run dev:
export YOUTUBE_IMPORT_URL=http://127.0.0.1:8791/youtube
npm run dev
```

Para usar **Cloudflare Containers**, configura `YOUTUBE_IMPORT_CONTAINER=true` y `YOUTUBE_IMPORT_TOKEN` en el entorno de Alchemy. Con Docker en marcha, `npm run dev` prueba el binding local y `npm run deploy:dev` construye y despliega la imagen con el Worker. El Worker inicia un contenedor privado mediante un Durable Object. El mismo token se transmite al proceso Python al iniciarlo.

También puedes configurar `YOUTUBE_IMPORT_URL` para un servicio HTTPS externo con el mismo secreto. Para repetir una demo con una pista previamente obtenida en un importador ejecutado por separado, monta el directorio privado con archivos `<videoId>.json3` y configura `YOUTUBE_CAPTIONS_DIR` en el proceso Python. Cualquier otro vídeo usa `yt-dlp`. Chrome llama únicamente al Worker.

```sh
curl -i http://127.0.0.1:8787/api/runs/youtube \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://youtu.be/DEJF6IGRuxA","fromSeconds":120,"toSeconds":180,"submissionKey":"f363c747-8f5f-4a61-9dbc-4ad431c09dc3","explanationLanguage":"ca"}'
```

El importador trabaja con subtítulos. Incluye las intervenciones de la pista que se solapan con el intervalo, de modo que un subtítulo en el borde puede empezar un poco antes o acabar un poco después. Los tiempos guardados son absolutos respecto al vídeo. Un intervalo sin subtítulos utilizables devuelve `422`. Los fallos de acceso a YouTube o del importador devuelven `503`.

## Recover checks and change explanation language

The web results page and text extension expose retry controls for technical failures and an English/Spanish/Catalan explanation selector. Retrying a failed claim preserves successful and active siblings. Extraction retries reuse saved section checkpoints; failed explanation retries reuse retained evidence. Mutations use a caller-generated UUID commandId, reused after a lost response. New deliberate attempts use a fresh UUID.

`POST /api/runs/:runId/retry` takes `{ "commandId": "UUID", "claimId": "optional existing failed claim ID" }`. Omitting claimId retries failed stages. `POST /api/runs/:runId/language` takes `{ "commandId": "UUID", "language": "en" }` (also es/ca). Both return `{ runId, commandId }` with202. Reusing an ID for a different mutation returns409.

Language changes translate only explanation/uncertainty from retained assessments, cache each language against its immutable source artifact, and preserve verdicts, evidence and arithmetic. Poll while `run.translation.status` is processing even if the checking run is complete. New assessment completions respect the latest selected language. The YouTube panel links to the same web result for these controls.
