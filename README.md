# Council Check

A text-based council claim checker. TASK-001 provides a saved-submission workflow in the web app. Claim extraction and evidence research are implemented by subsequent tasks.

## Run the app locally

Use Node.js 22.18 or newer and npm.

```sh
npm install
npm run dev
```

Open http://localhost:8787. Paste text, save it, and reload the resulting URL. The scaffold Workflow marks the submission as awaiting processing. Local submissions persist under the ignored Alchemy state directory in tooling/infra. Keep that directory to retain local data.

Local development emulates Workers, R2, a SQLite Durable Object, and Workflows using Alchemy/Miniflare. The pinned Alchemy provider requires an account identity even in local mode, so the infrastructure script supplies a local-only emulator identity. Cloudflare, OpenAI, and database credentials are unnecessary for this task's local path.

The web assets are built when dev starts. For frontend hot reload, keep the main dev process running and start `npm run dev --workspace @council/web` in another terminal. Open Vite's URL. It proxies /api to port 8787. Rebuild or restart the main dev command to serve updated frontend assets on port 8787.

## Checks and development deployment

```sh
npm run typecheck
npm run lint
npm run build
npm test
```

Build creates the web assets and dry-runs Worker bundling. The test command discovers future application tests and succeeds when none exist. TASK-001's behavioral validation used the running local Worker and a browser, including response-loss replay with the same submission key.

To deploy a development environment, authenticate with `npx alchemy login` or supply Cloudflare credentials in a root .env using .env.example. Set ALCHEMY_PASSWORD to encrypt deployment state, then run `npm run deploy:dev`. The account needs access to Workers, R2, Durable Objects, and Workflows. Alchemy provisions the bucket, bindings, Workflow, and SQLite Durable Object migration. Deployment credentials are server-side. Local and deployed data use separate stores.

The checked-in Wrangler configuration supports dry-run builds and standalone Wrangler local inspection. Alchemy owns infrastructure deployment. Both configurations pin compatibility date 2026-07-15 to match the pinned Alchemy emulator.

## Submission API

`POST /api/runs` accepts the following JSON and returns HTTP 202 with runId and a relative web URL.

```json
{
  "submissionKey": "a UUID generated by the caller",
  "text": "Original text to preserve",
  "explanationLanguage": "ca",
  "source": { "url": "https://example.org/source", "title": "Council passage" },
  "passages": [{ "start": 0, "end": 12, "speaker": "Councillor", "startSeconds": 10 }]
}
```

Only submissionKey and text are required. Text must contain a non-whitespace character and be at most 200,000 Unicode characters. Passage offsets are JavaScript UTF-16 offsets into the original text, and end is exclusive. Original whitespace is preserved. The limit counts Unicode code points.

Reuse a submissionKey after a lost response. The same validated payload returns the original run, while a different payload with that key returns HTTP 409. The browser retains its current draft/key in session storage and generates a new key when text changes. `GET /api/runs/:runId` returns the saved submission, stage, timestamp, and revision. Invalid or missing IDs return HTTP 404. Links grant access to submissions in this single-user scaffold.

# Datos del verificador del pleno de Barcelona

PostgreSQL 17 con pgvector. Las filas publicadas se consultan con SQL y los embeddings del catálogo se pueden añadir después. La carga funciona sin backend.

## Arranque local

Requiere Docker Compose y Python 3.10 o posterior.

```sh
docker compose up -d --wait
python3 -m venv .venv
.venv/bin/pip install -r scripts/requirements.txt
.venv/bin/python scripts/ingest.py
```

La base se llama `council`, escucha en localhost y utiliza el usuario `council`. Si cambias `POSTGRES_PORT` o `POSTGRES_PASSWORD`, exporta las variables para que las lean tanto Compose como el script. El script también acepta `DATABASE_URL`.

```sh
# Verificar todas las descargas y los parsers sin Docker, pip ni credenciales
python3 scripts/ingest.py --check

# Cargar solo Incasòl y los dos CSV más recientes del padrón
.venv/bin/python scripts/ingest.py --source incasol --source population --population-files 2

# Con OPENAI_API_KEY exportada, añadir vectores a las fichas ya cargadas
.venv/bin/python scripts/ingest.py --embed-only

# Con GOOGLE_FACT_CHECK_API_KEY exportada, guardar una búsqueda opcional
.venv/bin/python scripts/ingest.py --source fact-check --fact-query 'lloguer Barcelona'
```

Por defecto se descargan todos los CSV del padrón que CKAN anuncia. La carga continúa si falla una fuente, informa del error y sale con código distinto de cero. Cada fuente se escribe en una transacción. Volver a cargar el mismo recurso conserva su versión y actualiza la fecha de la última descarga. Los CSV mantienen las columnas y los valores originales como JSONB, incluidos ceros iniciales en códigos. INE queda en una fila por observación, con los campos de su serie. Las fichas se vectorizan con `text-embedding-3-small` y el vector se vuelve a generar si cambia su texto.

```sql
SELECT dataset_id, count(*) AS resources, sum(row_count) AS rows
FROM latest_snapshot
GROUP BY dataset_id
ORDER BY dataset_id;

SELECT s.resource_url, s.sha256, r.row_number, r.data
FROM latest_snapshot AS s
JOIN source_row AS r ON r.snapshot_id = s.id
WHERE s.dataset_id = 'incasol'
LIMIT 5;
```

Para buscar por similitud, obtén el vector de la consulta con el mismo modelo y ordena las fichas por `embedding <=> $1::vector`. El catálogo inicial es pequeño y usa distancia exacta. Las comparaciones factuales se hacen con las filas y sus periodos.

### Caso de referencia de Incasòl

Este ejemplo compara el segundo trimestre de 2025 con el de 2026 para el municipio de Barcelona (`08019`) y el tramo publicado `> 600 euros/mes`. La comparación usa datos oficiales y sirve como caso de integración.

```sh
docker compose exec -T db psql -XAt -v ON_ERROR_STOP=1 -U council -d council \
  -v baseline_year=2025 -v baseline_period=abril-juny \
  -v target_year=2026 -v target_period=abril-juny \
  < scripts/incasol-comparison.sql
```

En la descarga comprobada, la renta media de este tramo pasó de **1.135,55** a **1.140,89 €/mes** (+**0,47 %**). El JSON incluye las filas originales, el identificador y el hash del snapshot, la URL del CSV y la fórmula. Añade `-v snapshot_id=ID` para repetir la consulta contra un snapshot concreto de tu base. Con `target_year=2099` el script devuelve `missing_period` y conserva la fila disponible.

### Preparar pasajes de documentos oficiales

Después de crear las tablas base de `db/schema.sql`, aplica las migraciones antes de extraer documentos. Docker aplica el esquema base al crear un volumen vacío. En una base Neon nueva, aplica primero `db/schema.sql`. Los scripts usan `DATABASE_URL` cuando está exportada.

```sh
.venv/bin/pip install -r scripts/requirements.txt
.venv/bin/python scripts/extract_documents.py --migrate-only
.venv/bin/python scripts/ingest.py --source council --source minutes
.venv/bin/python scripts/extract_documents.py
```

Las migraciones de `db/migrations` se aplican por número y se registran en `schema_migration` en la misma transacción. El extractor guarda un pasaje por página con texto en el PDF y bloques de texto en el HTML. Se puede reprocesar una sola versión con `--snapshot-id ID`. Los bytes originales y los pasajes de otras versiones se conservan. Un PDF sin texto queda como `empty_or_scanned`. Los formatos sin extractor quedan como `unsupported` y los fallos de parser como `error` con su diagnóstico.

La cobertura comprobada es la portada del Consell Municipal y el acta del 31 de octubre de 2025. Los enlaces de la portada identifican documentos potenciales.

```sql
SELECT s.resource_url, s.sha256, p.snapshot_id, p.passage_number,
       p.page_number, p.html_location, p.passage_text
FROM source_document_passage p
JOIN snapshot s ON s.id = p.snapshot_id
WHERE s.dataset_id = 'minutes'
  AND p.search_vector @@ plainto_tsquery('simple', 'sessió ordinària')
ORDER BY p.page_number
LIMIT 3;
```

### Consultar la evidencia desde el Worker local

Añade `LOCAL_EVIDENCE_DATABASE_URL=postgresql://council:council_local@127.0.0.1:5432/council` y un `ALCHEMY_PASSWORD` en el `.env` local. Usa tus valores si cambiaste el puerto o las credenciales de Docker. Alchemy usa la contraseña para cifrar el estado del binding. Arranca PostgreSQL y ejecuta `npm run dev`.

```sh
curl -fsS http://127.0.0.1:8787/api/dev/evidence/catalogue
curl -fsSG http://127.0.0.1:8787/api/dev/evidence/documents \
  --data-urlencode 'datasetId=minutes' --data-urlencode 'q=sessió ordinària'
```

Con el `snapshotId` y `passageNumber` devueltos, recupera el mismo pasaje en `/api/dev/evidence/documents/<snapshotId>/<passageNumber>`. Las rutas de inspección solo se habilitan en el Worker local de Alchemy. Para un despliegue, `HYPERDRIVE_ORIGIN` configura el origen Neon mediante su URL directa de PostgreSQL.

Consulta las filas de Incasòl desde el Worker local:

```sh
curl -fsS http://127.0.0.1:8787/api/dev/evidence/query-dataset \
  -H 'Content-Type: application/json' \
  -d '{"datasetId":"incasol","resourceKey":"qww9-bvhh","filters":{"municipalityCode":"08019","year":"2025","period":"abril-juny","priceBand":"> 600 euros/mes"}}'
```

Para comparar con 2026, cambia `year` y añade el `snapshotId` devuelto en `snapshot.id`. Los periodos y tramos se filtran por su etiqueta exacta. Si el periodo no aparece, la respuesta tiene `rows: []`. Una fila publicada con renta vacía conserva su valor original y devuelve `rent.value: null`.

El catálogo local también admite búsqueda textual con `GET /api/dev/evidence/catalogue?q=lloguer` e inspección de recursos y versiones con `GET /api/dev/evidence/catalogue/incasol`.

La misma ruta admite estas fuentes. Obtén `resourceKey` del catálogo y reutiliza `snapshotId` para las páginas siguientes.

| `datasetId` | Filtros |
| --- | --- |
| `population` | `referenceDate` con formato `AAAA-01-01`. Opcionales `districtCode`, `neighbourhoodCode` y `censusSection`. |
| `tourist-flats` | `districtCode` y `neighbourhoodCode` opcionales, tal como salen en el CSV (por ejemplo, `"01"`). La fecha de descarga figura en el snapshot. |
| `ine-59061` | `seriesCode` (por ejemplo, `IPVA4962`) y `year` de cuatro dígitos. La respuesta conserva los códigos de unidad y escala del INE. |
